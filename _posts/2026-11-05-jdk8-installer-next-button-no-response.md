最近在 Windows 上安装 Oracle JDK 8 Update 341 时，安装向导打开正常，但点击欢迎页的“下一步”后没有任何反应。重新以管理员身份运行安装程序，结果仍然一样。下面记录这次排查的依据和最终可用的处理方法。

## 问题现象

使用的是 `jdk-8u341-windows-x64.exe`。安装窗口能够显示，后台也能看到安装进程，但点击“下一步”后没有进入后续配置页面。最初检查时，系统里已有 `java` 命令，`javac` 却不可用，因此不能仅凭 `java -version` 判断 JDK 已安装。

## 如何判断卡在哪里

我先检查了安装包的数字签名，结果为有效，签名方是 Oracle America, Inc.。随后查看安装日志：图形安装停留在欢迎页相关的界面初始化记录，没有看到正式安装完成的信息。单看任务管理器里“进程仍在运行”，并不能证明安装正在推进。

重新以管理员身份启动后，“下一步”仍无响应。由此可以确认，**这次卡住的是图形安装流程**；但现有日志没有指出是哪一个组件或设置导致按钮失效。欢迎页涉及内嵌网页组件，兼容性问题只是可能的解释，不能当成已证实的根因。

## 解决方法：静默安装

同一个安装包支持静默参数。先关闭卡住的安装窗口，再打开**管理员命令提示符**，把下面的安装包路径替换成自己电脑上的实际路径：

```bat
"C:\path\to\jdk-8u341-windows-x64.exe" /s /L "%TEMP%\jdk-install.log"
```

- `/s`：静默安装，不显示安装向导。
- `/L`：指定日志文件，方便检查安装结果。

这次运行的安装程序返回码是 `0`；日志显示 **Java SE Development Kit 8 Update 341 (64-bit) 安装成功**。安装目录为 `C:\Program Files\Java\jdk1.8.0_341`。随后直接运行该目录中的程序，确认版本：

```bat
"C:\Program Files\Java\jdk1.8.0_341\bin\java.exe" -version
"C:\Program Files\Java\jdk1.8.0_341\bin\javac.exe" -version
```

两者均显示 `1.8.0_341`。这一步比只看安装窗口更可靠：既确认运行环境存在，也确认编译器已经安装。

## 安装后找不到 `javac`

安装成功后，我在一个**安装前就打开**的命令提示符里执行 `javac -version`，仍然得到“不是内部或外部命令”。检查后发现，`javac.exe` 文件存在，系统环境变量也已经保存：

```text
JAVA_HOME=C:\Program Files\Java\jdk1.8.0_341
Path 中包含 %JAVA_HOME%\bin
```

原因是旧命令窗口还在使用启动时读取的环境变量。关闭并重新打开终端即可；如果暂时要在当前 `cmd` 窗口使用，可以执行：

```bat
set "PATH=C:\Program Files\Java\jdk1.8.0_341\bin;%PATH%"
javac -version
```

这条 `set` 只改变当前窗口。若需要长期使用，应在 Windows 的系统环境变量中设置 `JAVA_HOME`，并把 `%JAVA_HOME%\bin` 加入系统 `Path`。

## 中文帮助出现乱码

直接输入 `java` 会显示帮助信息。如果中文帮助乱码，通常是终端代码页与输出编码不一致，可以在当前命令提示符中尝试：

```bat
chcp 936
java
```

查看安装版本应使用 `java -version` 和 `javac -version`，不需要依赖帮助文字是否正常显示。

## 小结

这次的可验证结论是：图形安装停在欢迎页，而相同安装包的静默安装成功，JDK 与编译器版本检查也通过。**静默安装解决了安装问题，但没有证明图形界面卡住的具体根因。**遇到类似情况时，先看安装日志是否真正进入安装阶段，再尝试静默模式，并在结束后分别验证 `java` 与 `javac`。
